# 师傅创作流程

本文是 [`SKILL.md`](SKILL.md) 的中文译本。代理、工具链和校验仍以英文版为准；若两份文档不一致，以英文版为准。

## 核心规则

- 保持草稿状态、发布状态和历史日志之间的分离。
- 结构变更应走专门的 shifu helper 模块，而不是在路由里直接改树。
- 导入/导出 payload 的变更，要与校验、权限和历史行为同步。

## 工作流

1. 从 `route.py`、`funcs.py` 以及相关的 `shifu_*` helper 模块开始。
2. 判断这次变更影响的是草稿状态、发布状态，还是两者都有。
3. 当 payload 契约变化时，一并更新权限、结构校验和导入/导出行为。
4. 在 `src/api/tests/service/shifu/` 下新增或更新测试。

## 回归检查清单

- 草稿保存和重新加载。
- 发布路径。
- 如果 payload 形状变了，检查导入/导出。
- 权限失败路径。
