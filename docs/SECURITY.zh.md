# 安全

本文是 [`SECURITY.md`](SECURITY.md) 的中文译本。代理、工具链和校验仍以英文版为准；若两份文档不一致，以英文版为准。

## 原则

- 不要把密钥和环境相关凭据放进版本化文档、脚本、compose 文件，以及生成的指令镜像中。
- 让浏览器冒烟测试走现有本地开发栈，不要引入特权绕过。
- 优先使用 request-id 关联和 trace 提示，而不是把大范围日志倾倒到面向用户的输出中。
- 让本地可观测性服务在开发中保持匿名或仅本地；不要把它们暴露成远程生产依赖。

## 仓库规则

- 共享指令必须继续禁止硬编码密钥和环境相关 URL。
- 生成的知识文件不得嵌入密钥值。
- 诊断脚本可以展示请求范围的证据，但在 request id 缺失或含糊时，必须避免打印无关日志历史。
- 本地可观测性 compose 配置可以为 Grafana、Loki、Tempo、Prometheus 和 OTEL 暴露仅回环端口，但不得要求提交密钥。

## 后续关注点

- 如果可观测性扩展到仅本地开发之外，必须先记录访问控制、保留策略和凭据处理，再扩大范围。
- 如果浏览器冒烟覆盖扩展到经过鉴权的第三方提供方，提供方凭据必须继续留在现有配置层后面。
